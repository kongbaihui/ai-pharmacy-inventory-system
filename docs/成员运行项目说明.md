# AI医院药品进销存信息管理系统——成员运行项目说明

本文供项目组成员在 Windows 环境下拉取并运行完整工程。项目采用前后端分离结构，后端、Web 前端和 App 需要分别启动。

## 一、项目目录

```text
ai-pharmacy-inventory-system/
├─ RuoYi-Vue-master/       后端工程（Spring Boot、MyBatis、Maven）
├─ RuoYi-Vue2-master/      Web 管理端（Vue 2、Element UI）
├─ RuoYi-App-master/       移动端（uni-app）
├─ docs/                   项目文档
└─ sql/                    原始业务 SQL 备份
```

后端数据库脚本以 `RuoYi-Vue-master/sql/` 目录中的版本为准。

## 二、运行环境

建议安装以下环境：

| 环境 | 建议版本 | 用途 |
| --- | --- | --- |
| JDK | 17 或 21 | 运行后端，项目编译版本为 Java 17 |
| Maven | 3.8 以上 | 下载依赖、启动或打包后端 |
| MySQL | 8.0 | 保存系统与药品业务数据 |
| Redis | 5.0 以上 | 登录令牌、验证码及缓存 |
| Node.js | 16 或 18 | 运行 Vue 2 Web 前端 |
| npm | 随 Node.js 安装 | 安装 Web 前端依赖 |
| HBuilderX | 较新版本 | 运行 uni-app 移动端 |

先检查常用环境：

```powershell
java -version
mvn -version
node -v
npm -v
```

## 四、初始化 MySQL 数据库

### 4.1 创建并选择数据库

在 Navicat、DataGrip 或 MySQL 客户端中执行：

```sql
CREATE DATABASE IF NOT EXISTS `ry-vue`
DEFAULT CHARACTER SET utf8mb4
COLLATE utf8mb4_general_ci;

USE `ry-vue`;
```

运行脚本前可以执行以下语句，确认当前数据库正确：

```sql
SELECT DATABASE();
```

结果必须是 `ry-vue`，否则会出现 `No database selected` 或数据导入到错误数据库的问题。

### 4.2 全新数据库执行顺序

按以下顺序执行 `RuoYi-Vue-master/sql/` 中的脚本：

1. `ry_20260417.sql`：若依用户、角色、权限和基础表。
2. `quartz.sql`：定时任务相关表。
3. `01_med_schema.sql`：药品、供应商、库存、批次、盘点和预警等业务表。
4. `03_stock_business.sql`：入库、出库、退库业务单及明细表。
5. `02_med_menu.sql`：药品基础资料和库存监管菜单。
6. `04_web_menu.sql`：Web 菜单整合、库存业务入口及侧边栏顺序。

注意事项：

- `ry_20260417.sql` 和 `01_med_schema.sql` 包含删除并重建表的语句，有数据后不要重复运行。
- `02_med_menu.sql` 不是重复执行脚本，重复运行可能产生重复菜单。
- `04_web_menu.sql` 可重复执行，用于更新当前项目侧边栏。
- 已完成数据库初始化的成员，更新菜单时只运行最新的 `04_web_menu.sql`。

```text
RuoYi-Vue-master/ruoyi-admin/src/main/resources/application.yml
```

中的 `spring.data.redis.password` 配置。

## 六、启动后端

### 6.1 修改数据库连接

打开：

```text
RuoYi-Vue-master/ruoyi-admin/src/main/resources/application-druid.yml
```

确认主数据源配置与本机 MySQL 一致：

```yaml
url: jdbc:mysql://localhost:3306/ry-vue
username: root
password: "本机MySQL密码"
```

密码包含 `#`、`:` 或空格时必须加引号。不要把个人数据库密码提交到 GitHub。

### 6.2 使用开发工具启动

使用 IntelliJ IDEA 打开 `RuoYi-Vue-master`，等待 Maven 依赖下载完成，然后运行：

```text
com.ruoyi.RuoYiApplication
```

### 6.3 使用命令行启动

```powershell
cd RuoYi-Vue-master
mvn -pl ruoyi-admin -am spring-boot:run
```

后端默认地址：

```text
http://localhost:8080
```

后端启动成功时，控制台不会再出现数据库连接或 Redis 连接异常。

## 七、启动 Web 管理端

打开新的 PowerShell 窗口：

```powershell
cd RuoYi-Vue2-master
npm install
npm run dev
```

如果 `npm install` 出现旧版依赖冲突，使用：

```powershell
npm install --legacy-peer-deps
npm run dev
```

项目默认 Web 端口为 `80`。如果端口被占用，可以临时换端口：

```powershell
$env:port=81
npm run dev
```

然后访问控制台输出的本地地址，例如：

```text
http://localhost
http://localhost:81
```

Web 开发代理默认连接 `http://localhost:8080`，因此应先启动后端。

### 7.1 正常侧边栏顺序

管理员登录后应看到：

1. 药品库存工作台
2. 药品进销存管理
3. AI前端界面
4. 系统监控
5. 系统管理
6. 系统工具

“若依官网”默认隐藏。普通用户需要管理员在“系统管理 → 角色管理”中分配对应菜单和按钮权限。

执行菜单 SQL 后必须退出账号并重新登录，仅刷新浏览器不会重新获取完整权限菜单。

## 八、启动 App

使用 HBuilderX 打开：

```text
RuoYi-App-master
```

当前 App 配置文件为：

```text
RuoYi-App-master/config.js
```

仓库中的默认 `baseUrl` 仍指向若依官方演示接口。运行本项目 App 前应改成本机后端地址。

模拟器可根据网络环境使用：

```js
baseUrl: 'http://localhost:8080'
```

真机不能使用 `localhost`，需要改成开发电脑的局域网 IP，例如：

```js
baseUrl: 'http://192.168.1.10:8080'
```

同时确保手机和电脑在同一局域网，并允许 Windows 防火墙访问后端端口。

## 十、常见问题

### 10.1 `No database selected`

运行 SQL 前没有选择数据库。先执行：

```sql
USE `ry-vue`;
```

### 10.2 `Access denied for user 'root'@'localhost'`

`application-druid.yml` 中的 MySQL 用户名或密码与本机不一致。使用能正常登录 MySQL 的账号和密码修改配置。

### 10.3 `'vue-cli-service' 不是内部或外部命令`

Web 依赖尚未安装。在 `RuoYi-Vue2-master` 中执行：

```powershell
npm install --legacy-peer-deps
```

### 10.4 首页正常但没有药品菜单

确认后端连接的数据库与执行 SQL 的数据库相同，然后运行：

```sql
SELECT DATABASE();
SELECT menu_name, path, component, visible, status
FROM sys_menu
WHERE menu_name = '药品进销存管理'
   OR component LIKE 'system/%';
```

如果没有“药品进销存管理”，全新数据库依次执行 `02_med_menu.sql`、`04_web_menu.sql`；已有该菜单时只执行 `04_web_menu.sql`。之后退出账号并重新登录。

### 10.5 后端提示 Redis 连接失败

确认 Redis 已启动，且 `application.yml` 中的地址、端口和密码与本机一致。

### 10.6 Web 请求返回 404 或 500

- 404：检查对应后端接口是否已经实现，以及前端代理是否连接 8080 端口。
- 500：查看后端控制台最早出现的异常，常见原因是 SQL 未执行、字段不一致或数据不符合业务规则。

## 十一、成员提交代码注意事项

提交前执行：

```powershell
git status
git diff
```

不要提交以下内容：

- `node_modules/`、`target/`、`dist/`、日志和临时文件。
- 本机 MySQL、Redis、模型密钥等个人配置。
- 与本人任务无关的大范围格式化或目录改名。
- 未确认用途的其他成员代码删除。

推荐提交流程：

```powershell
git pull origin main
git add 需要提交的文件
git commit -m "类型: 简要说明"
git push origin main
```

如果拉取时存在冲突，不要直接覆盖其他成员代码，应先确认冲突文件所属模块再合并。
