# AI 医院药品进销存信息管理系统——成员运行项目说明

本文供项目组成员在 Windows 环境下拉取、配置、运行和验证最终工程。最终交付只包含后端、Web 管理端、后端数据库脚本和自动验证配置，不再包含旧移动端或根目录重复 SQL。

## 1. 最终目录与职责

```text
ai-pharmacy-inventory-system/
├─ RuoYi-Vue-master/            后端主工程
│  ├─ ruoyi-admin/              启动入口、Web 控制器和配置
│  ├─ ruoyi-system/             药品、库存、AI 服务和测试代码
│  └─ sql/                      唯一有效的数据库脚本目录
├─ RuoYi-Vue2-master/           最终 Web 管理端
├─ .github/workflows/verify.yml 自动测试和生产构建
├─ docs/成员运行项目说明.md      本文
└─ README.md                    项目总览
```

后续不要再从旧 `RuoYi-App-master/` 或根目录 `sql/` 复制代码。数据库脚本一律以 `RuoYi-Vue-master/sql/` 为准。

## 2. 本机环境

建议安装：

| 环境 | 建议版本 | 用途 |
| --- | --- | --- |
| Git | 2.40+ | 拉取和提交代码 |
| JDK | 17 或 21 | 编译、运行后端 |
| Maven | 3.8+ | 后端依赖和测试 |
| MySQL | 8.0 | 系统与业务数据 |
| Redis | 5.0+ | 登录令牌、验证码和缓存 |

在 PowerShell 中确认环境：

```powershell
git --version
java -version
mvn -version
mysql --version
node -v
npm -v
```

`mvn -version` 显示的 Java 主版本应为 17 或更高。若电脑安装了多个 JDK，应先修正 `JAVA_HOME`。

cd ai-pharmacy-inventory-system

## 4. 初始化 MySQL

### 4.1 创建数据库

使用 Navicat、DataGrip 或 MySQL 客户端执行：

```sql
CREATE DATABASE IF NOT EXISTS `ry-vue`
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_general_ci;
USE `ry-vue`;
SELECT DATABASE();
```

`SELECT DATABASE()` 必须返回 `ry-vue`，否则脚本可能报 `No database selected` 或被导入到错误数据库。

### 4.2 全新数据库脚本顺序

按顺序执行 `RuoYi-Vue-master/sql/` 中的文件：

1. `ry_20260417.sql`：用户、角色、菜单、字典、日志等若依基础表。
2. `quartz.sql`：定时任务相关表。
3. `01_med_schema.sql`：药品分类、供应商、药品、库存、批次、流水、盘点、预警和过期清理表。
4. `03_stock_business.sql`：入库、出库、退库业务单与明细表，并补充批次唯一索引。
5. `02_med_menu.sql`：药品基础资料和库存监管菜单、按钮权限。
6. `04_web_menu.sql`：最终侧边栏、业务菜单、AI 菜单及 `common` 普通角色权限。

默认管理员账号：

```text
账号：admin
密码：admin123
```

### 4.3 已有数据库如何更新

- `03_stock_business.sql` 可重复执行，用于补齐进销存业务表与唯一索引。
- `04_web_menu.sql` 可重复执行，用于修正最终菜单和普通角色权限。
- `05_common_role_permissions.sql` 只重置 `common` 角色菜单，适合不想重新执行完整菜单整合脚本的已有数据库。
- `ry_20260417.sql`、`quartz.sql` 和 `01_med_schema.sql` 含删表重建逻辑，有业务数据后禁止重复执行。
- `02_med_menu.sql` 会新增菜单，不应在同一数据库中反复执行。

执行菜单或权限脚本后，退出当前账号并重新登录。单纯刷新浏览器不会重新获取完整动态菜单。

## 5. 本地配置

### 5.1 创建个人配置文件

复制示例文件：

```powershell
Copy-Item RuoYi-Vue-master\.env.example RuoYi-Vue-master\.env.local
```

编辑 `RuoYi-Vue-master/.env.local`：

```properties
spring.datasource.druid.master.url=jdbc:mysql://localhost:3306/ry-vue?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
spring.datasource.druid.master.username=root
spring.datasource.druid.master.password=你的MySQL密码

spring.data.redis.host=localhost
spring.data.redis.port=6379
spring.data.redis.password=
```

`.env.local` 已被 Git 忽略。所有成员都应把本机数据库、Redis 和模型密钥放在此文件中，不要再修改并提交公共配置中的真实密码。

### 5.2 AI 配置（可选）

要使用对话、RAG 和 AI 月报，在同一个 `.env.local` 中继续填写：

```properties
AI_CHAT_PROVIDER=openai
AI_CHAT_BASE_URL=https://你的OpenAI兼容模型服务地址
AI_CHAT_API_KEY=你的模型服务密钥
AI_CHAT_MODEL=你的模型名称
```

不使用 AI 时保留 `AI_CHAT_PROVIDER=none`，或不填写 AI 项。后端仍可启动，基础资料、进销存和库存监管功能不受影响。

知识库运行文件默认生成在 `RuoYi-Vue-master/runtime/ai/knowledge/`，该目录不会提交到 GitHub。

## 6. 启动顺序

### 6.1 启动 MySQL 和 Redis

确认 MySQL 中已经存在 `ry-vue` 数据库，并确认 Redis 可以连接 `localhost:6379`。Redis 设置了密码时，必须同步填写 `.env.local`。

### 6.2 启动后端

命令行方式：

```powershell
cd RuoYi-Vue-master
mvn -pl ruoyi-admin -am spring-boot:run
```

IDEA 方式：

1. 用 IntelliJ IDEA 打开 `RuoYi-Vue-master`。
2. 等待 Maven 项目和依赖加载完成。
3. 运行 `com.ruoyi.RuoYiApplication`。

后端默认地址：`http://localhost:8080`。

启动成功后，控制台不应出现数据库拒绝连接、Redis 拒绝连接或端口占用异常。

### 6.3 启动 Web 管理端

新开一个 PowerShell 窗口：

```powershell
cd RuoYi-Vue2-master
npm install --legacy-peer-deps
npm run dev
```

Web 默认使用 80 端口，并把 `/dev-api` 代理到 `http://localhost:8080`。浏览器访问：

```text
http://localhost
```

若 80 端口被占用，可临时改用其他端口：

```powershell
$env:port=81
npm run dev
```

然后访问 `http://localhost:81`。

## 7. 功能验收顺序

管理员登录后建议按以下顺序检查：

1. 首页“药品库存工作台”能显示药品、库存、预警、临期统计和 12 个月趋势。
2. “药品进销存管理 → 基础资料”能维护药品分类、药品信息和供应商。
3. 新建入库单并确认，批次、总库存和库存流水同步增加。
4. 新建出库单并确认，系统拒绝过期批次或超库存数量。
5. 新建退库单并确认，退回数量不会超过原批次累计入库数量。
6. “库存监管”能完成盘点审核、预警扫描、有效期刷新和过期清理确认。
7. AI 已配置时，导入资料并重建知识库，随后验证问答引用、库存工具和月报。
8. 用普通账号登录，确认只能看到已授权的药品业务和 AI 菜单，不能进入系统管理菜单。

关键业务规则：

- 草稿单据可以修改或删除，已确认单据不可修改或删除。
- 所有库存变化必须同步写入库存流水。
- 盘点审核、清理确认会锁定单据和批次，库存期间发生变化时要求重新创建盘点。
- 库存预警扫描会更新现有预警、自动关闭已恢复预警，并新增当前有效预警。

## 8. AI 页面使用

AI 主要接口：

```text
POST /system/ai/chat
POST /system/ai/chat/stream
POST /system/ai/knowledge/import
POST /system/ai/knowledge/rebuild
GET  /system/ai/report/data
POST /system/ai/report/stream
```

首次使用：

1. 使用有 AI 权限的账号进入“AI 前端界面”。
2. 导入药品说明书、药房制度等资料。
3. 点击“重建知识库”。
4. 等待状态显示“就绪”。
5. 再测试资料问答、引用来源和库存分析。

若模型密钥未配置，AI 请求会提示服务未配置；这不代表后端整体启动失败。

## 10. 常见问题

### `No database selected`

导入脚本前执行 `USE ry-vue;`，并用 `SELECT DATABASE();` 确认当前数据库。

### `Access denied for user 'root'@'localhost'`

检查 `.env.local` 中的数据库用户名和密码；确认 MySQL 用户允许从本机连接。

### 后端提示 Redis 连接失败

确认 Redis 服务已启动，地址、端口和密码与 `.env.local` 一致。

### `'vue-cli-service' 不是内部或外部命令`

前端依赖尚未安装，在 `RuoYi-Vue2-master` 中执行：

```powershell
npm install --legacy-peer-deps
```

### Web 请求返回 404

确认后端已在 8080 端口启动，并确认当前终端位于最终 `RuoYi-Vue2-master`，不是旧前端副本。

### 首页正常但没有药品菜单

确认后端连接的数据库就是执行 SQL 的数据库，依次检查 `02_med_menu.sql` 和 `04_web_menu.sql` 是否执行成功，随后退出账号重新登录。

### AI 页面提示知识库未就绪

先导入资料并执行“重建知识库”。如果仍失败，检查后端控制台和 `runtime/ai/knowledge/` 的写入权限。

### 端口被占用

后端 8080 被占用时先停止冲突程序；Web 80 被占用时使用 `$env:port=81` 临时切换端口。
