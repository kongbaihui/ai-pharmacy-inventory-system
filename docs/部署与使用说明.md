# 部署与使用说明

## 一、环境要求

后端：若依前后端分离版（Spring Boot 3 + MyBatis + MySQL 8），JDK 17。前端：若依前端工程（Vue2 + Element UI）。数据库与 Redis 按项目原有配置启动即可。

## 二、数据库脚本执行顺序

1. 执行 `sql/01_med_schema.sql`：创建药品分类、供应商、药品信息、库存、批次、库存流水、盘点、预警、过期清理共 10 张表，并写入演示数据（含库存不足、库存积压、临期、过期各一条样例）。脚本中表结构使用 `drop table if exists`，重复执行会清空这些表的数据。
2. 执行 `sql/02_med_menu.sql`：创建一级目录“药品进销存管理”，下设“基础资料”和“库存管理”两个目录及七个子菜单，并写入对应的查询、新增、修改、删除、导出、审核、扫描、处理等按钮权限。菜单编号使用“当前最大菜单编号 + 1”自动生成，不会与已有菜单冲突。

## 三、后端代码放置位置

| 本目录文件 | 项目中对应位置 |
| --- | --- |
| main/java/com/ruoyi/system/domain/*.java | ruoyi-system 模块 com/ruoyi/system/domain |
| main/java/com/ruoyi/system/mapper/*.java | ruoyi-system 模块 com/ruoyi/system/mapper |
| main/java/com/ruoyi/system/service/*.java | ruoyi-system 模块 com/ruoyi/system/service |
| main/java/com/ruoyi/system/service/impl/*.java | ruoyi-system 模块 com/ruoyi/system/service/impl |
| main/java/com/ruoyi/system/controller/*.java | ruoyi-admin 或 ruoyi-system 模块 com/ruoyi/system/controller |
| main/resources/mapper/system/*.xml | ruoyi-system 模块 resources/mapper/system |

复制完成后重新编译启动后端。若项目中开启了 MyBatis 别名扫描，实体类放在 `com.ruoyi.system.domain` 包下即可被 mapper XML 中的短类名直接引用，无需额外配置。

复制完成后重新执行前端启动命令，并强制刷新浏览器，菜单会自动从后端加载。

## 五、菜单权限配置

脚本执行后，使用管理员账号进入“系统管理 → 角色管理”，编辑对应角色，在菜单权限树中勾选“药品进销存管理”下的菜单，保存后重新登录即可看到菜单。若只想让部分岗位查看预警和处理盘点，可只勾选对应子菜单及按钮权限。

## 六、功能使用顺序建议

1. 先维护基础资料：药品分类 → 供应商信息 → 药品信息（库存上下限与临期预警天数在此设置）。
2. 入库业务完成后再进行库存管理操作，批次数据由入库业务产生，也可在“药品有效期”页面手工补录。
3. 定期在“药品有效期”页面点击“刷新效期状态”，把批次状态同步为正常、临期、过期。
4. 在“库存预警”页面点击“扫描生成预警”，系统按库存上下限与有效期生成预警，业务人员处理后填写处理说明。
5. 发现过期药品时，在“过期药品清理”页面选择批次发起清理申请，确认后系统扣减库存并生成库存流水。
6. 需要核对账实一致性时，在“库存盘点”页面新建盘点单，带出账面明细后录入实盘数量，提交后由管理员审核，审核即完成库存调整。

## 七、常见问题

删除分类提示存在子分类或已关联药品：属于正常校验，需先处理下级数据。删除批次提示仍有剩余库存：需先把剩余数量出库或清理为 0。盘点单无法修改或删除：已审核的盘点单为保证库存可追溯，不允许再修改。清理单无法删除：已确认的清理单已产生库存流水，不允许删除。
