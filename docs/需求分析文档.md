# AI 医院药品进销存信息管理系统——需求分析文档

## 一、项目目标

本系统基于 RuoYi-Vue，用于医院药房药品基础资料、入库、出库、退库、库存盘点、库存预警、有效期与过期清理等业务的信息化管理，并为后续智能问答、库存分析和数据看板提供可靠数据。

本文档只维护胡振鹏负责的入库、出库、退库、库存流水、库存实时更新与模块整合需求。药品分类、药品信息、供应商、盘点、预警、有效期与过期管理沿用现有设计，本次不修改。

## 二、用户与业务场景

| 用户 | 主要业务 |
| --- | --- |
| 药库管理员 | 登记入库、出库、退库业务单，确认业务并查询库存流水 |
| 药房负责人 | 查看业务单状态与库存变化，追溯业务来源 |
| 系统管理员 | 配置权限并部署数据库脚本和后端代码 |

## 三、功能需求

### 3.1 药品入库

1. 新增入库草稿，登记业务日期、供应商、经办人和备注。
2. 明细登记药品、生产批号、生产日期、有效期、入库数量与采购单价。
3. 数量必须为正；批号和有效期必填；生产日期不得晚于有效期。
4. 同一张单据中同一药品与批号不得重复。
5. 确认时创建或累计批次，增加总库存并生成入库流水。

### 3.2 药品出库

1. 新增出库草稿，登记业务日期、领用科室、经办人和备注。
2. 明细必须选择已有批次并填写正数数量。
3. 已过期批次禁止出库；批次或总库存不足时禁止确认。
4. 确认时扣减批次剩余数量和总库存，并生成出库流水。

### 3.3 药品退库

1. “退库”指科室将未使用药品退回药库，库存增加。
2. 草稿登记退回科室、原药品批次、数量、经办人和备注。
3. 退库后批次剩余数量不得超过该批次累计入库数量。
4. 确认时增加批次剩余数量和总库存，并生成退库流水。

### 3.4 库存流水与单据

1. 流水记录药品、批次、业务类型、变动数量、变动前后库存、来源单号、操作人和时间。
2. 草稿可修改、删除且不影响库存；已确认单据不可修改或删除。
3. 单据确认、批次更新、总库存更新和流水登记必须处于同一事务，任一步失败全部回滚。
4. 确认时锁定单据和批次，避免重复确认及并发超量出库。

## 四、统一库存规则

1. 药品总库存通过现有 `IMedStockService.adjustStock` 统一变更。
2. 任何扣减都不得使总库存或批次剩余数量小于零。
3. 每次变更必须生成对应流水，并关联来源业务单。
4. 批次数量变更后刷新效期状态。

## 五、接口需求

| 接口 | 方法 | 说明 | 权限 |
| --- | --- | --- | --- |
| `/system/stockOrder/list` | GET | 查询业务单 | `system:stockOrder:list` |
| `/system/stockOrder/{orderId}` | GET | 查询单据与明细 | `system:stockOrder:query` |
| `/system/stockOrder` | POST | 新增草稿 | `system:stockOrder:add` |
| `/system/stockOrder` | PUT | 修改草稿 | `system:stockOrder:edit` |
| `/system/stockOrder/confirm/{orderId}` | PUT | 确认并更新库存 | `system:stockOrder:confirm` |
| `/system/stockOrder/{orderIds}` | DELETE | 删除草稿 | `system:stockOrder:remove` |
| `/system/stockOrder/flow/list` | GET | 查询库存流水 | `system:stockOrder:flow` |

## 六、数据需求

新增 `med_stock_order` 和 `med_stock_order_item` 两张业务表。继续使用现有 `med_stock`、`med_stock_batch` 和 `med_stock_flow`，不修改原表结构。

## 七、验收标准

1. 入库、出库、退库确认后，批次和总库存同步变化并生成对应流水。
2. 库存不足、批次不足、过期批次出库、超量退库均被拒绝，且不产生部分更新。
3. 同一单据不能重复确认，已确认单据不能修改或删除。
4. 可按条件分页查询业务单和库存流水。
